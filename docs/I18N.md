# Translations (i18n)

Hournook is available in 15 languages: English (source and fallback), Ελληνικά, Español,
Français, Deutsch, Italiano, Português, Русский, Türkçe, Polski, Nederlands, 中文, 日本語,
हिन्दी and العربية (right to left). Everything a business or its customers see is
translated. The platform admin area (`/admin`) is English only.

## Where the language comes from

| Surface                               | Language                                                                                                              |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Marketing and legal pages             | URL prefix: `/el/pricing`, `/ar`. English has no prefix. A first visit follows the language cookie, then the browser. |
| Sign-in, sign-up and other auth pages | Language cookie (`hn_locale`), then the browser's Accept-Language                                                     |
| Onboarding, dashboard, settings       | The account's language (`users.locale`), chosen in onboarding next to the time zone and changed in Settings → Account |
| Public booking page, embed, manage    | `?lang=xx` (remembered in `hn_booking_locale`), otherwise the business's booking-page language (`businesses.locale`)  |
| Emails to customers                   | The language the customer booked in (`appointments.locale`)                                                           |
| Emails to account holders             | The recipient's account language (`users.locale`)                                                                     |

`src/server/i18n.ts#getLocale()` implements this per request. `src/proxy.ts#resolveLocale()`
handles the URL part.

## Using translations

Catalogues are JSON files: `src/lib/i18n/messages/{locale}/{namespace}.json`. English is the
source of truth. After adding a namespace run `npm run i18n:registry` (the generated
`src/lib/i18n/registry.ts` gives typed keys; never edit it by hand).

Server components, server actions, route handlers:

```tsx
import { getT, getFormatLocale } from '@/server/i18n'
const t = await getT('app-calendar')
t('toolbar.today')
t('summary', { count: 3 }) // "{count, plural, one {# booking} other {# bookings}}"
formatDate(date, tz, await getFormatLocale())
```

Client components get catalogues from a server `<Translations ns={[…]}>` wrapper above them
(usually in a layout), then:

```tsx
'use client'
import { useT, useLocale } from '@/components/i18n/provider'
const t = useT('app-calendar')
const { tag } = useLocale() // BCP 47 tag for Intl / src/lib/format.ts helpers
```

Outside a request (emails, jobs): `await translator(locale, 'email')` from `src/lib/i18n/load.ts`.

Sentences with a link or emphasis stay one message:

```tsx
import { rich } from '@/components/i18n/rich'
rich(t('agree'), { terms: (c) => <Link href="/terms">{c}</Link> })
// en: "I agree to the <terms>Terms of Service</terms>."
```

### Message syntax

- Variables: `Hello {name}`.
- Plurals: `{count, plural, =0 {No bookings} one {# booking} other {# bookings}}`. Use the
  target language's plural categories: ru/pl `one few many other`; ar
  `zero one two few many other`; zh/ja only `other`; the rest `one other`. `#` is the
  localized number.
- Select: `{role, select, owner {Owner} other {Member}}`.
- Rich text: `<tag>…</tag>` (no nesting). Translations must keep the same tag names.

The unit tests (`tests/unit/i18n.test.ts`) fail when a language is missing a key, has an extra
key, or uses different variables or tags than English.

### Rules

1. The English wording stays exactly as it was when a string is moved into a catalogue (E2E
   tests and screenshots rely on it).
2. Never translate: the brand "Hournook", people's and businesses' own content (names,
   service names, descriptions they typed), email addresses, URLs, the company's legal
   identifiers (ΑΦΜ, ΓΕΜΗ, address).
3. Keys are nested by screen and component in camelCase: `settings.account.language.label`.
4. Dates, times, numbers and money are formatted with the page's locale tag, never a
   hard-coded `'en'` / `'en-GB'` (the `en-CA` trick for `YYYY-MM-DD` keys is fine).
5. Right-to-left: use logical Tailwind classes (`ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`,
   `end-*`, `text-start`, `text-end`, `border-s`, `border-e`, `rounded-s-*`, `rounded-e-*`)
   instead of `ml/mr/pl/pr/left/right/text-left/text-right`. Arrows and chevrons that point
   "forward" get `rtl:-scale-x-100`.
6. `node scripts/i18n-scan.mjs <paths>` lists hard-coded text left in JSX. Data arrays in
   `.ts` files (feature lists, FAQ, options) must be moved into catalogues too; the scanner
   does not see them.
7. Legal pages in another language show `common:language.translationNote` at the top: the
   English text is the binding one.

## Tone and glossary

Write like a native speaker writing product copy, not a literal translation: short, warm,
clear. Buttons are short verbs.

| Language | Register                                                               |
| -------- | ---------------------------------------------------------------------- |
| el       | Polite plural (εσείς): «Συνδεθείτε», «Αποθήκευση»                      |
| es       | tú, neutral Spain Spanish                                              |
| fr       | vous                                                                   |
| de       | Sie                                                                    |
| it       | tu                                                                     |
| pt       | European Portuguese (pt-PT), polite third person / impersonal          |
| ru       | вы (lower case)                                                        |
| tr       | siz                                                                    |
| pl       | ty (friendly product tone), infinitive-free imperatives on buttons     |
| nl       | je/jij                                                                 |
| zh       | Simplified Chinese, 您 where addressing the user                       |
| ja       | です/ます                                                              |
| hi       | आप, Devanagari, common English loanwords where Hindi speakers use them |
